# CloakFile

CloakFile takes a document, strips out sensitve information, and returns completely new file
using safe placeholders.

```
ORIGINAL                                        SANITIZED
John Doe's phone number is 514-555-1234.        [PERSON_001]'s phone number is [PHONE_001].
His email is john.doe@example.com.              His email is [EMAIL_001].
His credit card is 4111 1111 1111 1111.         His credit card is [CREDIT_CARD_001].
```

The result is safe to hand to an external AI service, a vendor, or a support
ticket, removing any sensetive info from the file.

> **Status: Phase 2.** TXT, CSV, JSON and PDF work end to end. DOCX is
> deliberately unimplemented. PDF output is **text, not a visual copy** of the
> original — see [PDF support](#pdf-support). This has not had a security
> review. See [Security limitations](#security-limitations) before using it
> with real data

---

## Core Principles


**1. Everything stays local.**
No part of the core pipeline calls an external API. There is no LLM, no OCR
service, no telemetry. Detection is deterministic and runs locally. ESLint
blocks network and LLM imports inside `packages/` so this cannot erode by
accident.

**2. Replacement, not concealment.**
Drawing a black box over text is a visual redaction, it does not actually protect your privacy.
CloakFile replaces the characters completely

| Mode               | What it means                                                     | Acceptable? |
| ------------------ | ----------------------------------------------------------------- | ----------- |
| `text-replacement` | Original characters are gone; a placeholder stands in their place | Yes         |
| `content-removal`  | Original characters are gone entirely (metadata, annotations)     | Yes         |
| `visual-redaction` | Pixels cover the text; the text is still extractable              | **No**      |


**3. verify, then hand the file.**
Every sanitized document is re-read from its generated bytes and searched for
the values we said we removed. If any survive, the download is refused. "We
could not check" is reported as `inconclusive`, requiring a reupload.

**4.The browser sees as little as possible.**
The API has no field for an original value. The frontend receives placeholders
and masked previews (`Visa •••• 1111`), The original values never leave the backend.

**5. Nothing is kept.**
Documents live in memory for the duration of one session and are then gone.
There is no database of documents and no permanent mapping of placeholders to
original values.

## How it's organized 

```
UPLOAD → VALIDATE → EXTRACT → DETECT → ASSIGN PLACEHOLDERS
       → [ user review ] → ANONYMIZE → GENERATE → VERIFY → DOWNLOAD → DELETE
```

This codebase is an npm-workspaces monorepo. The frontend and the HTTP layer are thin; all the
real logic lives in framework-free packages.

```
apps/
  web/                    React + Vite + Tailwind. Rendering only.
  api/                    Fastify. Upload validation, sessions, HTTP mapping.
packages/
  shared/                 Types, errors, wire contract, privacy preview policy.
  detection/              Detector interface, registry, overlap resolution, detectors.
  anonymization/          Placeholder allocation and text rewriting.
  document-processing/    Format sniffing, extractors, generators.
  verification/           Proves the output no longer contains the originals.
  pipeline/               Composes the above. Knows nothing about HTTP.
tests/
  integration/            Cross-package round-trip and API tests.
  fixtures/               Synthetic sample documents.
docs/                     Architecture, security, threat model, development.
```

Full detail: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

# Getting Started

## Setup

Needs Node.js 22.13+ 

```bash
git clone <repository-url>
cd cloakfile
npm install          # installs every workspace
cp .env.example .env # optional; it runs fine on defaults
npm run dev          # starts API on 3001 and web on 5173
```

`vite` or `tsx` **not recognized**, You forgot to run npm install or you were not inside the repo

`esbuild` **install scripts warning** if windows policy blocks npm or esbuilds from downloading/executing

## PDF Parsing Stuff

PDF works, with one trade-off,

> **The sanitized PDF is text, not a visual copy of the original.** Layout,
> fonts, images, colours and tables are not preserved.

that is an outcome we tried to avoid but here is why we could not:


1. **Modern PDFs use "subset fonts" .** Basically PDF file only stores gylth IDs, 
 that are the specfic characters used in the original document with the exact font style,
 these are mapped to random codes,`John Doe` as `1002003202302332` for example. this makes it
 impossible to parse. as the font could literally not contain the `[` or `_` for example 


2. **A page is only one of the places a value can be.** there is many more places text can hide in
invisible OCR layer,comments, notes, metadata. a normal read would not be enough

So instead of editing the uploaded PDF, we decided to pull text out of every one of those compartments
and build a completly new PDF from scratch containing only the clean parsed text.

| Input                              | Result                                                                          |
| ---------------------------------- | ------------------------------------------------------------------------------- |
| Text PDF, any fonts or positioning | Sanitized. But loses layout                                                      |
| Form fields, annotations, comments | Text extracted, sanitized, then showed as labeled text                           |
| Metadata, XMP, bookmarks           | Deleted, user is informed of their removal                                       |
| Embedded files / attachments       | Deleted                                                                          |
| Invisible OCR text layers          | Extracted and sanitized like any other text                                      |
| **Scanned / image-only pages**     | **Refused.** No text to extract, so process is `inconclusive` and the download is blocked |
| Non-Latin scripts                  | currently comes out as `?`, counted and reported. - Known limitation             |
| Digitally signed PDFs              | Deleted — a rebuilt document is a different document                             |

## What actually works right now

- TXT, CSV, JSON and PDF end to end: upload → detect → replace → verify →
  download
- Detects: email, phone (international, via libphonenumber-js), credit card
  (Validated with Luhn Checksum), US SSN, IP address, URLs, custom regex 
  that you can apply, and names /organizations via compromise
- Same value gets the same placeholder for consistency 


## What is intentionally not built

- **DOCX** extraction and generation — registered, documented, and fails loudly
- PDF layout preservation 
- Address, government ID, bank account and date-of-birth detection — registered
  as stubs that report themselves as unimplemented
- OCR and scanned documents
- Authentication, accounts, persistence, multi-instance deployment

## Known issues / things to be careful about
- Name detection will miss names it doesn't recognize and occasionally flags random capitalized words as people. Don't rely on it alone for    anything that actually matters.
- The verification step can only prove something is gone from content it can actually read. If a page is a scanned image, nothing can be      guaranteed about what's in it, which is exactly why those get refused instead of silently passed.
- Uploads are fully stored in memory, which caps how big a file can be and means this can't scale as big as easily. That was a deliberate choice to avoid writing temp files to disk (which brings its own security headaches).
- Literally anyone who can reach the API can upload a document — there's no auth at all right now.
- I've only tested the PDF code against sample files I made myself. A messy real-world PDF from the wild might break something I haven't   thought of
